LLMs Can Write Their Own Recovery Hints

Can a model write useful redundancy before it knows which part of a document will be deleted?

Mustafa Anis Hussain · Qwen/Qwen3.5-4B · FineWeb-Edu · Tinker

TL;DR. A Qwen3.5-4B model learned to write a short, readable backup before it knew which passage would be deleted. Across 400 held-out documents, that pre-committed redundancy made the correct missing tokens more likely at both tested scales, helped tokens that were not copied into the backup, and remained useful to an untouched decoder. The experiment shows that ordinary vocabulary tokens can serve as a practical recovery aid for damaged text.

The idea

Imagine saving a long document together with one very short note. You do not know what will go wrong later. A paragraph may disappear from the beginning, middle, or end. Your note must therefore preserve information that is useful across many possible future losses.

That is the task in this project. A writer language model reads an intact document and produces a short sequence of ordinary text tokens, which we call redundancy. Only after the writer has finished do we choose a contiguous span to delete. A decoder then sees the damaged document and the redundancy and tries to recover the missing text.

OriginalMarie Curie moved to Paris in 1891 to study physics.

RedundancyCurie · Paris · 1891 · physics

Later damageMarie Curie moved to Paris in 1891 to study physics.

The redundancy above would be useful for that deletion, but the writer was not told that this particular phrase would disappear. It had to decide in advance that the person, place, date, and subject were worth protecting. That pre-commitment is what separates error correction from ordinary repair. If the writer saw the hole first, it could simply copy the missing sentence.

The communication channel is deliberately restricted. The writer may output only tokens already present in Qwen3.5-4B’s vocabulary. It cannot invent new embeddings, pass hidden activations, or attach a binary file. The resulting message can be printed, inspected, and given to an entirely separate model through an ordinary text prompt.

The claim we actually test

The basic question is whether the same decoder considers the true missing text more likely when redundancy is present than when it sees only the damaged document. Stronger tests ask whether the benefit survives when copied words are excluded, whether an untouched decoder can use the message, and whether reinforcement learning improves the writer beyond simply prompting the base model.

Architecture and training

We ran the same idea at two text scales. Throughout the article, 512/24 means a 512-token document with a 24-token deletion and a redundancy budget of at most 24 tokens. 1024/48 doubles all three lengths. Both preserve the same ratio: the deleted span and redundancy each occupy about 4.7% of the document.

512 / 24512-token document24-token redundancy24-token holefour future deletions
1024 / 481,024-token document48-token redundancy48-token holefour future deletions

Both roles use LoRA adapters on the same Qwen3.5-4B base model and exactly the same tokenizer. The writer is trained with reinforcement learning because its output is sampled text. The decoder is trained with ordinary supervised cross-entropy because the exact deleted tokens are known.

The decoder never sees four holes simultaneously. For each document we create four separate single-hole examples. Every writer candidate faces the same four locations, so candidates are compared on identical damage rather than luck.

It helps to think of this as an insurance problem. The writer has a tiny budget and must insure the whole document against an accident whose location has not yet been announced. The decoder is the claims adjuster: it sees what survived and uses the pre-committed redundancy to infer what was lost. A summary is one possible insurance policy, but not necessarily the best one. Predictable prose needs little protection; an isolated date, surname, negation, or identifier may be impossible to recover unless the writer spends some of its budget on it.

One optimization step

  1. Sample two redundancy candidates for each intact document.
  2. After sampling finishes, select four deletions. The 1024/48 run assigns one to each document quarter; the earlier 512/24 run samples four positions without that constraint.
  3. Score every exact target token with and without each candidate.
  4. Construct a group-relative advantage for each writer candidate.
  5. Update the writer LoRA with Tinker importance sampling.
  6. Update the decoder LoRA with weighted cross-entropy.
  7. Refresh the writer sampling client from current weights.

How success is measured

NLL means negative log-likelihood

A language model does not merely output one next token. It assigns a probability to every token in its vocabulary. If the correct next token receives probability 0.20, the model considers it twice as plausible as when it receives probability 0.10. We need a score that captures these probability changes even when the model’s top choice remains wrong.

Negative log-likelihood, or NLL, does exactly that. For a deleted span \(Y=(y_1,\ldots,y_T)\), we average the negative logarithm of the probability assigned to each correct token:

\[ \operatorname{NLL}(Y) =-\frac{1}{T}\sum_{t=1}^{T} \log p(y_t\mid \text{context},y_{<t}). \]

Lower NLL is better. For one correct token, probability \(0.10\) gives NLL \(-\log 0.10=2.30\); raising that probability to \(0.20\) lowers NLL to \(1.61\). A perfect probability of \(1\) would have NLL \(0\). The logarithm turns a product of token probabilities into a sum, and averaging over \(T\) lets us compare 24-token and 48-token holes on the same per-token scale.

Why compare NLL with and without redundancy?

Every damaged example is scored twice by the same decoder. First it sees the damaged document alone. Then it sees the identical document and target with redundancy added. We report

\[ \Delta\operatorname{NLL} = \operatorname{NLL}_{\text{without}} - \operatorname{NLL}_{\text{with}}. \]

A positive value means the redundancy helped. Because this difference is measured in natural-log units per target token, it has a direct probability interpretation:

+0.01 ΔNLL\(e^{0.01}=1.010\)

about 1% more probability per correct token

+0.05 ΔNLL\(e^{0.05}=1.051\)

about 5% more probability per correct token

+0.08 ΔNLL\(e^{0.08}=1.083\)

about 8% more probability per correct token

What does a full-span ΔNLL of \(+0.05\) mean? For one 24-token target, the improvement in teacher-forced log likelihood is \(24\times0.05=1.2\) nats. Therefore:

\[ \frac{P_{\mathrm{with}}(Y)}{P_{\mathrm{without}}(Y)} = e^{1.2} \approx 3.3. \]

This is a ratio between the two models’ teacher-forced likelihoods of the known target sequence. It does not say that free generation reconstructs the span 3.3 times as often. When \(+0.05\) is an average across many examples, \(3.3\) is the corresponding geometric-mean likelihood ratio; individual spans can benefit by more, by less, or not at all.

Why not use exact reconstruction as the reward?

Exact span recovery is extremely sparse. A 24-token answer is marked wrong if 23 tokens are correct and one comma differs. Early in training, almost every generated span is wrong, so exact match provides almost no guidance. ΔNLL is dense: every correct token tells us whether the redundancy moved the decoder in the right direction.

We calculate this score with teacher forcing. When scoring token \(y_t\), the decoder receives the correct earlier target tokens \(y_{<t}\), not its own previous guesses. This isolates the probability assigned at each position. We separately evaluate free generation, where early mistakes can compound.

Separating copying from indirect help

A writer can help by placing an important missing word directly in the redundancy. That is valid backup, but it is different from helping the decoder infer a word that was never copied. We therefore classify target positions as:

  • covered: the token ID or normalized surface text appears in the redundancy;
  • uncovered: the recognizable token text is absent.

The strict writer reward averages ΔNLL only over uncovered positions. If the target contains height and the writer emits PrinterCheckHeight, that position is treated as covered. The writer may still preserve it, and the decoder still trains on it, but that direct backup cannot masquerade as indirect recovery.

Let \(U_{i,m}\) be the target positions that are uncovered for writer candidate \(i\) under deletion mask \(m\). For those positions, the mask-specific reward is

\[ r_{i,m} = \frac{1}{|U_{i,m}|} \sum_{t\in U_{i,m}} \left( \ell^{+}_{i,m,t} - \ell^{-}_{m,t} \right), \]

where \(\ell^{+}\) is the correct-token log probability with redundancy and \(\ell^{-}\) is the correct-token log probability without it. A candidate’s scalar reward averages the four future deletions:

\[ R_i = \frac{1}{M}\sum_{m=1}^{M}r_{i,m} - \lambda\frac{|Z_i|}{Z_{\max}}. \]

The length term makes longer messages pay for their extra bandwidth. In the two final fixed-budget runs, \(\lambda=0\), because all candidates were already constrained to the same maximum length and the scientific question had shifted to helping genuinely uncovered tokens.

How the writer and decoder learn

Writer RL algorithm: GRPO-style group-relative policy gradient using Tinker importance_sampling.

It is not DPO: there is no fixed preference dataset, reference-policy comparison, or pairwise logistic loss. It is not PPO: the probability ratio is not clipped and we do not take several epochs over stale rollouts. The configured advantage_clip=5 clips unusually large centered advantages only; it is not PPO ratio clipping. The closest concise description is an on-policy, REINFORCE-style update with group-relative advantages and an importance-sampling correction.

For each document the writer samples two candidate recovery notes. Both candidates face the same four deletion masks. In the 512/24 run, each candidate’s four mask rewards were averaged and the two candidate rewards were centered. In the later 1024/48 run, candidates were compared separately inside each document quarter and the four centered comparisons were averaged. Ties produce no writer update.

More precisely, candidates are centered separately for every deletion mask:

\[ \widetilde A_{i,m} = \frac{r_{i,m}-\operatorname{mean}_{j}(r_{j,m})} {\operatorname{std}_{j}(r_{j,m})+\varepsilon}, \qquad A_i=\frac{1}{M}\sum_{m=1}^{M}\widetilde A_{i,m}. \]

This mask-relative version gives every document quarter an equal vote. One excellent deletion cannot conceal three poor ones. With two candidates, a non-tied mask usually contributes approximately \(+1\) to its winner and \(-1\) to its loser.

The writer tokens were sampled by a rollout policy. During the update, importance sampling corrects for any difference between that rollout distribution and the current training policy:

\[ \rho_{i,t} = \exp\left( \log\pi_{\theta}(z_{i,t}\mid X,z_{i,<t}) - \log\pi_{\mathrm{rollout}}(z_{i,t}\mid X,z_{i,<t}) \right). \]

Tinker then minimizes the token-wise objective \(\mathcal L_{\mathrm{writer}}=-\sum_{i,t}\rho_{i,t}A_i\). Conceptually, this increases the probability of sampled tokens when \(A_i>0\) and decreases it when \(A_i<0\), with \(\rho_{i,t}\) correcting any small difference between the rollout and learner policies. Prompt positions receive zero advantage, so only generated recovery-note tokens can update the writer. This follows Tinker’s documented importance-sampling loss.

Code: one Tinker decoder and writer optimization step

Tinker computes the decoder cross-entropy backward pass first. Our local code converts its target log probabilities into rewards and advantages, then sends rollout log probabilities and advantages back through Tinker’s importance_sampling loss.

Two numbers that appear similar on a dashboard mean different things here. A candidate’s raw reward is its uncovered-token ΔNLL, measured in natural-log units per missing token; \(+0.05\) is already about a 5% probability increase per correct token. Its advantage asks only whether that candidate was better than the other candidate for the same document. We deliberately center the two advantages, so one might receive \(+1\) and the other \(-1\). Their mean is zero by construction. A zero average advantage is therefore normal; a group in which both candidates tie at zero is the warning sign.

This is the writer’s raw uncovered-token reward during training, smoothed over nearby steps. It is noisy because every batch contains different documents and deletion locations. The important scale is hundredths of a nat per token: \(+0.05\), for example, means about 5% more probability on each correct uncovered token. A policy-gradient run is not expected to produce a clean supervised-learning curve here.

The decoder has a simpler job. It receives cross-entropy gradients on every correct deleted token:

\[ \mathcal L_{\mathrm{decoder}} = -\sum_{t} w_t \log p_{\phi}(y_t\mid X^{-},Z,y_{<t}). \]

Prompt positions have \(w_t=0\). Deleted target tokens have weight \(1\) in assisted examples and weight \(0.5\) in bare-infilling examples. The latter keeps the no-redundancy baseline competent, so the measured gain cannot rise merely because the decoder forgot how to work without the writer.

What we found

With the architecture and measurement defined, we can now ask the central empirical question: did a message committed before corruption make the later missing text easier to recover? Across 400 held-out documents and four deletion locations per document, the answer was yes at both tested scales.

A short message written before the deletion made the true missing text less surprising afterward. The effect survived longer documents, longer deletions, and a decoder that had never participated in co-training. Random vocabulary tokens did not produce the same result.

The message helped even when it did not contain the answer

Some of the gain comes from direct backup: the writer preserves a name, date, or technical term that later happens to be deleted. That is valid error correction. We also removed deleted tokens whose recognizable text appeared in the redundancy and scored only the remaining positions. Those uncovered tokens still improved by \(+0.0158\) ΔNLL at 512/24 and \(+0.0122\) at 1024/48, or roughly 1–2% more probability per correct token.

Both mechanisms contributed. The larger covered-token gain shows effective selective backup. The positive uncovered-token gain shows that topic cues and related facts also helped the decoder infer words that were not written directly in the message.

What happened during training

Two diagnostics helped us distinguish a genuinely useful redundancy channel from effects that could arise through direct lexical overlap or co-adaptation between the two LoRAs.

First, we tracked how often deleted target text appeared recognizably in the generated redundancy. Rising coverage is not automatically bad because the point of redundancy is to preserve information. It does, however, tell us whether the system is becoming a selective lexical backup rather than learning indirect cues.

This curve measures recognizable overlap between the generated redundancy and the later deleted span. The writer did not know the deletion location, so coverage reflects information that it elected to preserve in advance. It also motivated the stricter uncovered-token reward: otherwise direct copying could dominate the writer’s score.

Second, we periodically gave learned redundancy to the untouched base decoder. This asks whether the message remains useful to an ordinary Qwen3.5-4B reader, rather than only to the decoder LoRA that trained beside it.

Positive values mean learned redundancy helped an untouched decoder predict uncopied target tokens. The probe is volatile, but it remains evidence against a purely private code between the two LoRAs.

What training added

The end-to-end result is strong. Moving from an untouched writer and untouched decoder to the trained writer–decoder pair sharply reduced missing-token NLL. The complete system became much better at the reconstruction task, while its short redundancy continued to provide an additional benefit within the same trained decoder.

The writer-only benchmark below compares the prompted base writer with the writer trained by the GRPO-style, group-relative importance-sampling update described above. It is not a DPO or PPO benchmark.

The decoder learned the reconstruction format through supervised cross-entropy, which accounts for most of the end-to-end NLL drop. Alongside that large gain, the learned redundancy helped surface-uncovered target tokens by \(+0.0158\) ΔNLL at 512/24 and \(+0.0122\) at 1024/48. Even after excluding answers written recognizably in the message, the remaining correct tokens became about 1–2% more probable per token.

A prompted base writer was already a strong competitor: with the trained decoder held fixed, writer fine-tuning changed redundancy benefit by \(+0.0031\) at 512/24 and \(-0.0014\) at 1024/48. This is an encouraging practical result as well as a useful research boundary. Qwen3.5-4B can produce useful pre-committed redundancy from the prompt alone, while the full training procedure makes the overall reconstruction system substantially stronger.

Learned redundancy also transferred to the untouched decoder. The messages therefore remained broadly readable instead of depending on an opaque protocol shared only by the two trained LoRAs.

512 / 24 · Step 500 · National ID document

A compressed semantic index helped four different holes

What happened. The source repeatedly connected identity cards, legal ownership, government property, and the meaning of “identify.” The writer fused those concepts into an index-like string. All four independently sampled holes improved, while exact token-ID coverage was only 2.1%. The message supplied a useful conceptual frame even where it did not reproduce the missing token IDs.

512 / 24 · Step 450 · Peppermint document

A tiny medical mnemonic strongly recovered early facts

What happened. The writer preserved the document’s unusual entities and relationships in a terse mnemonic. For two first-quarter holes concerning peppermint, herpes simplex, and the herbal name Bo He, the mask reward rose by +0.607 and +0.786. Later holes moved by only about +0.007. This is a vivid success, but it also foreshadows the positional bias visible in the full evaluation.

1024 / 48 · Step 990 · Dioscoreaceae document

A readable botanical summary helped every quarter

What happened. Here the longer writer used its budget as a conventional scientific summary. Every quarter received a positive strict reward. This was the behavior we ultimately wanted: one pre-committed message that remained useful for widely separated possible deletions.

Limitation: recovery was still concentrated near the beginning

The balanced botanical example was not the dominant pattern. In the final held-out evaluation, almost all strict uncovered-token benefit came from holes in the first quarter of the document. At 512/24, Q1 improved by \(+0.0714\) ΔNLL while Q2–Q4 stayed near zero. At 1024/48, Q1 improved by \(+0.0548\), again with the other quarters near zero.

The system learned useful recovery, but not yet position-uniform recovery. Document openings often contain titles, definitions, and headline entities, and the writer’s summary-like messages tended to preserve them. The first 512/24 run sampled deletion positions randomly and was not position-aware. The 1024/48 run was position-aware: it sampled one mask per quarter and centered candidate advantages separately in each quarter before averaging them. The Q1 concentration persisted anyway. In a next iteration, we would shape this more directly, for example by optimizing the worst-performing quarter or requiring a positive reward floor in every quarter rather than merely giving each quarter one equal relative vote.
